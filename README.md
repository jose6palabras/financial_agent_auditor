## 📖 Project Overview

This project is a comprehensive end-to-end automation system designed to streamline the verification of daily financial movements. 
The primary objectives are to reduce manual operational tasks, increase overall efficiency, lower costs, and establish agile workflows within financial auditing. 

By combining Large Language Models (LLMs), serverless compute, and orchestrated data pipelines, the ecosystem autonomously evaluates financial reports in PDF format, 
compares them against ERP transactional records, and generates a pre-reconciled spreadsheet for human validation.

## 🛠️ Technology Stack

*   **Compute & AI Agent:** Docker, Google Cloud Run, Python 3.11, Google Agent Development Kit (ADK), Gemini API
*   **Orchestration & Logic:** Google Apps Script (V8)
*   **Database & Data Warehousing:** Google BigQuery
*   **File Storage:** Google Drive 
*   **Visualization & Operations:** Google Sheets, Google Data Studio (Looker)
*   **Security:** Google Secret Manager

## ⚙️ System Architecture & Automated Workflow

The architecture is split into two primary engines: an **Autonomous AI Agent** handling triage and cognitive extraction, 
and a **GAS Orchestrator** managing file routing and data reconciliation.

### Phase 1: Ingestion & AI Triage (Cloud Run + Gemini)
A containerized AI agent continuously monitors a designated Gmail inbox for incoming financial reports.
1. **Policy Validation:** The agent reads incoming emails to ensure content, structure, and submission policies are met.
2. **Rejection Flow:** If an email is non-compliant or missing data, the agent marks the email as read and autonomously replies to the sender
detailing the exact errors that require correction.
4. **Approval & AI Extraction:** If the email is compliant, the agent extracts the PDF attachment and uses a specific prompt to verify the data via Gemini.
5. The structured output (JSON) is saved securely to BigQuery, and the email is left as "Unread" to trigger the next system phase.

### Phase 2: Orchestration & Hierarchical Storage (Google Apps Script)
Operating within a strict execution window (08:20 AM to 08:20 PM), the GAS orchestrator processes the validated emails in batches.
1. **Metadata Extraction:** The script extracts user codes and identifies whether the submission is a standard report or a missing document (`--FALTANTE--`).
2. **Drive Hierarchy:** Attachments are renamed and dynamically routed into a standardized hierarchical folder structure in Google Drive (`Root -> Agency -> Year -> Month -> Day`).
3. **Completion:** The email is finally marked as read, closing the inbox ingestion loop.

### Phase 3: Centralized Reconciliation (BigQuery)
BigQuery serves as the central data repository, pre-loaded with transactional data from the company's ERP system.
1. **Data Fetching:** The GAS orchestrator queries the dynamic daily transaction tables (e.g., `movimientos_{year}{month}{day}`).
2. **AI JSON Retrieval:** Simultaneously, the script fetches the analyzed JSON output previously generated by the AI agent.

### Phase 4: Report Generation & Human Review (Google Sheets)
1. **Template Cloning:** A standardized Google Sheets template is duplicated and moved to the specific daily folder in Drive.
2. **Data Flattening:** The script cross-references the AI's extracted data against the ERP's transactional records.
3. **Automated Verification:** Each line item is evaluated and automatically tagged as either **Doc 0k** (Matched) or **Faltante** (Missing).
4. **Analyst Handoff:** The finalized, pre-audited spreadsheet is left ready for a human Operations Analyst to perform the final review.

### Phase 5: Operations Control Dashboard (Looker Studio)
To provide real-time visibility, the ecosystem feeds an operations tracking dashboard using BigQuery control views (like `vw_calendario_movimientos_{agencia}`). 
The dashboard utilizes a traffic-light tracking system:
*   ⚪ **Gray:** The agency has not yet sent the email.
*   🟡 **Yellow:** The report was received and processed by the AI, currently awaiting human review.
*   🟢 **Green:** The audit has been fully completed and validated by the Operations team.

## 🗄️ Core Database Schema

The BigQuery environment is structured around relational tracking and transactional matching:

*   **Transactional Data (`movimientos_{YYYYMMDD}`):** Stores core ERP fields including `TIP_DOC`, `NUM_DOC`, `FECHA_MOV`, `DEBITOS`, `CREDITOS`, and `USUARIO`.
*   **Audit Tracking (`registro_verificaciones`):** Logs the operational lifecycle, storing `id_movimiento`, `agencia`, `fecha_verificacion`, `responsable`, and `fecha_analista`.
